# Super Mario 64 for PSP

🇪🇸 [Léelo en español](README.es.md)

A native port of **Super Mario 64** (US version) for the **Sony PSP**, based on the
[sm64-port](https://github.com/sm64-port/sm64-port) / [n64decomp/sm64](https://github.com/n64decomp/sm64) decompilation
and the PSP port by [z2442](https://github.com/z2442/sm64-port).

**What this version adds**

- Choice of **30 or 60 FPS**, with frame-pacing options.
- Audio is generated by the PSP's **Media Engine** (the second CPU), which frees the main CPU for the game.
- An **in-game Options menu** (open it from the pause screen) with three pages: **Graphics**, **Audio** (music volume, effects volume and sound mode) and **Controls** (remap every button).
- All settings live in **one readable text file**, `sm64config.txt`, that you can also edit by hand.
- Progress is saved on the Memory Stick like a normal PSP game.

> **This repository does not contain the game's data.** You need your **own copy of the Super Mario 64 (US) ROM**,
> which the build process turns into the PSP version. No ROM is included and none will be provided.
> This is a fan project and is not affiliated with Nintendo.

## 1. What you need

| Thing | Details |
|---|---|
| **A PC** | Windows 10 or 11, 64-bit, about **10 GB of free disk space** and an internet connection (only for the first build). |
| **A Super Mario 64 ROM** | The **US** version, in **`.z64`** format (8 MB, "big-endian"). Its SHA-1 must be `9bef1128717f958171a4afac3ed78ee2bb4e86ce`. |
| **Docker Desktop** | Free for personal use. It provides the whole PSP compiler for you, so you do **not** have to install any developer tools. |
| **A PSP with custom firmware** | For example ARK-4 or PRO CFW, and a Memory Stick. *Or* the [PPSSPP](https://www.ppsspp.org/) emulator. |

The only thing you install on the PC is Docker Desktop. Everything else (compiler, Python, libraries) lives inside a Docker container
that the build script creates for you.

## 2. Building it on Windows, step by step

### Step 1 — Check your ROM

1. Make sure Windows shows **file extensions**: in File Explorer open **View → Show → File name extensions**.
   (If extensions are hidden, a file you rename to `baserom.us.z64` may secretly become `baserom.us.z64.z64`, and the build will not find it.)
2. Right-click the Start button → **Terminal** (or **Windows PowerShell**) and run, changing the path to where your ROM is:

   ```powershell
   Get-FileHash -Algorithm SHA1 "C:\path\to\your\rom.z64"
   ```

3. The result must be exactly `9BEF1128717F958171A4AFAC3ED78EE2BB4E86CE`.
   If it is different, your ROM is not the US version, or it is in another format (`.v64` / `.n64`). The build needs the `.z64` format.

### Step 2 — Install Docker Desktop

1. Download it from <https://www.docker.com/products/docker-desktop/> and run the installer.
   Keep the option **"Use WSL 2 instead of Hyper-V"** ticked (the default).
2. Restart the PC if the installer asks you to.
3. Open **Docker Desktop** from the Start menu and accept the terms. Wait until the bottom-left corner shows
   **"Engine running"** (green). **Docker Desktop must be open every time you build.**
4. To confirm it works, open a PowerShell window and run:

   ```powershell
   docker --version
   ```

   You should see something like `Docker version 27.x.x`.

> If Docker complains about **virtualization**, it has to be switched on in your PC's BIOS/UEFI
> (look for "Intel VT-x", "SVM Mode" or "Virtualization Technology" and enable it). See [Troubleshooting](#5-troubleshooting).

### Step 3 — Download the project

The easiest way, with no extra programs:

1. On this repository's page click the green **Code** button → **Download ZIP**.
2. Extract the ZIP into a **short folder without spaces or accents**, for example `C:\sm64-psp`.
   Avoid very long paths and avoid folders synced by OneDrive.

*(If you already use Git, `git clone https://github.com/Edwintendo/sm64-port-psp.git` works too.)*

### Step 4 — Put the ROM in the project folder

1. Copy your ROM into the project folder, **next to the file called `Makefile`**.
2. Rename it to exactly **`baserom.us.z64`** (all lowercase).

The folder should now contain, among others: `Makefile`, `build_psp.ps1`, `Dockerfile.psp`, `src`, and `baserom.us.z64`.

### Step 5 — Run the build script

1. Open the project folder in File Explorer, click an empty area of the address bar, type `powershell` and press **Enter**.
   (That opens PowerShell already inside the folder. On Windows 11 you can also right-click an empty area → **Open in Terminal**.)
2. Run:

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\build_psp.ps1
   ```

   (The `-ExecutionPolicy Bypass` part lets Windows run the script just this once, without changing any setting.)

3. Wait. The **first time** it does three things, and it is slow, so be patient:
   1. Downloads the PSP compiler and builds a small Docker image called `sm64psp` (a few minutes, needs internet).
   2. Extracts the graphics and sounds from your ROM.
   3. Compiles the game (this part takes the longest; the screen fills with text, which is normal).
4. When it finishes you will see:

   ```
   Listo: build\us_psp\mario64\  (copia EBOOT.PBP y SM64.PRX juntos a la misma carpeta de la PSP)
   ```

   Next builds are much faster: only what you changed is recompiled.

**Optional script switches**

| Command | What it does |
|---|---|
| `.\build_psp.ps1 -Clean` | Deletes the previous build first. Use it if something is broken or stuck. |
| `.\build_psp.ps1 -Opt O2` | Builds with `-O2` instead of `-O3` (separate folder: `build_O2\`). |
| `.\build_psp.ps1 -Rebuild` | Rebuilds the Docker image (only needed if `Dockerfile.psp` changes). |

(Remember to put `powershell -ExecutionPolicy Bypass -File` in front if you use them, e.g.
`powershell -ExecutionPolicy Bypass -File .\build_psp.ps1 -Clean`.)

### Step 6 — Find the result

The game is the pair of files **`EBOOT.PBP`** and **`SM64.PRX`** inside **`build\us_psp\mario64\`**. Always keep them together in the same folder: `EBOOT.PBP` is a tiny loader and `SM64.PRX` is the game itself (this makes it start much faster on a real PSP).

## 3. Putting it on your PSP (or running it in PPSSPP)

### On a real PSP

1. Connect the PSP to the PC with a USB cable and enable **USB Connection** from the XMB, *or* take the Memory Stick out and put it in a card reader.
2. On the Memory Stick, open the **`PSP`** folder, then **`GAME`**.
3. Create a new folder called **`SM64`** and copy **both** `EBOOT.PBP` and `SM64.PRX` into it, so the paths are:

   ```
   PSP\GAME\SM64\EBOOT.PBP
   PSP\GAME\SM64\SM64.PRX
   ```

4. Disconnect the PSP. On the XMB go to **Game → Memory Stick** and you will find **Super Mario 64**.

> Your PSP needs **custom firmware** (ARK-4, PRO, ME, …) to run homebrew. This port was developed and tested on a PSP with **ARK-4 at 333 MHz**.
> On a **PSP Go**, copy the folder to the internal storage's `PSP\GAME` folder instead.

### In PPSSPP (PC / Android)

Open PPSSPP and use **Load…** to pick `EBOOT.PBP` (keep `SM64.PRX` next to it), or drag the file onto the PPSSPP window.

## 4. Playing: controls, options menu and saves

### Default controls

| PSP | Does |
|---|---|
| **Analog stick** | Move Mario |
| **✕ Cross** | A (jump) |
| **□ Square** | B (punch / dive) |
| **○ Circle** or **L** | Z (crouch / ground pound) |
| **R** | R (camera mode) |
| **△ Triangle** | N64 "L" button (the game doesn't use it) |
| **D-pad** | C buttons (camera; Up = first-person view) |
| **Start** | Pause |

You can change all of these in the Options menu.

### The Options menu

1. Press **Start** to pause the game.
2. Press **R** (the pause screen shows "**R Options**" at the bottom right).

| Buttons | Action |
|---|---|
| D-pad / stick **up–down** | Move between options |
| D-pad **left–right** or **✕** | Change the value / enter a page |
| **□** or **○** | Go back |
| **Start** or **R** | Close the menu (and save everything) |

**Pages**

- **Graphics** — FPS Limit (30 / 60), Frame Pacing (*Keep FPS* / *Keep Speed*), Object Distance and Far Distance (100 %–300 %),
  Object Culling (*Original* / *Vertical*), FPS Counter, Show Sound CPU, Reset to Defaults.
- **Audio** — Music Volume and Effects Volume, from 0 to 100 (100 is the game's original loudness), and Sound Mode: Stereo, Mono or Headset. Sound Mode is the same setting as the one in the file-select screen (it is saved in the save file, so changing it in either place changes both).
- **Controls** — choose a button and press **✕**; the screen says "Press a button" — press the PSP button you want (it waits about 5 seconds).
  If that button was already used by another action, the two are swapped. Also Stick Deadzone and Reset to Defaults.

### Where things are saved

Everything is stored on the Memory Stick in `PSP\SAVEDATA\SM64PORT\`:

| File | Contents |
|---|---|
| `sm64_save_file.bin` | Your game progress (stars, coins…) |
| `sm64config.txt` | All your settings (graphics, audio, controls) as plain text |

`sm64config.txt` can be opened with Notepad. Each line is `name = value`. To start from scratch, delete the file (or use *Reset to Defaults*).

## 5. Troubleshooting

**`docker` is not recognized / "The term 'docker' is not recognized"**
Docker Desktop is not installed, or PowerShell was open before installing it. Install it, **close PowerShell and open a new one**.

**"error during connect…" / "Cannot connect to the Docker daemon" / "docker daemon is not running"**
Open **Docker Desktop** and wait for **"Engine running"**, then try again.

**Docker Desktop says WSL 2 or virtualization is not available**
- Run `wsl --install` in an administrator PowerShell and restart.
- Enable virtualization in the BIOS/UEFI (Intel VT-x / AMD SVM).

**"running scripts is disabled on this system"**
Start the script exactly like this: `powershell -ExecutionPolicy Bypass -File .\build_psp.ps1`.

**`Failed to open baserom.us.z64!`**
The ROM is not in the right place or has the wrong name. It must sit **next to `Makefile`** and be called exactly `baserom.us.z64`
(with extensions visible, check it is not `baserom.us.z64.z64`).

**`baserom.us.z64 has the wrong hash!`**
It is not the US ROM, or it is in another format. Redo [Step 1](#step-1--check-your-rom).

**The build stops with an error halfway, or you changed something and it behaves strangely**
Run it again with `-Clean`: `powershell -ExecutionPolicy Bypass -File .\build_psp.ps1 -Clean`.

**"No space left on device"**
Free some disk space (Docker needs a few GB). In Docker Desktop you can also run *Troubleshoot → Clean / Purge data*.

**The build is very slow**
The first one always is (see Step 5). Keep the project on a normal drive (not a network drive) and close heavy programs.
In Docker Desktop → Settings → Resources you can give it more CPUs.

**The game does not appear in the XMB**
Check the paths are exactly `PSP\GAME\SM64\EBOOT.PBP` and `PSP\GAME\SM64\SM64.PRX` (both files, same folder) and that your PSP has custom firmware. If you see a "Loading the game…" screen with an error, `SM64.PRX` is missing or in another folder. Re-copy the file if it is corrupt.

**Anything else**
Open an *Issue* on the repository's GitHub page and include the last 20–30 lines of the build output.

## 6. Building on Linux / WSL

You can use the same Docker image, from a Linux terminal (or inside WSL with Docker running), at the project root with `baserom.us.z64` in place:

```bash
docker build -t sm64psp - < Dockerfile.psp
docker run --rm -v "$PWD:/sm64" -w /sm64 sm64psp make TARGET_PSP=1 pbp VERSION=us -j$(nproc)
```

The result is again `build/us_psp/mario64/` (`EBOOT.PBP` + `SM64.PRX`). (On Linux, files created by Docker belong to `root`; fix it with `sudo chown -R $USER .` if you need to.)

**Without Docker**: install the [PSP toolchain (pspdev)](https://github.com/pspdev/pspdev), plus `python3` and `build-essential`/`audiofile` development packages, then:

```bash
make TARGET_PSP=1 VERSION=us -j4        # builds the ELF/PRX
make TARGET_PSP=1 VERSION=us pbp        # builds build/us_psp/mario64/{EBOOT.PBP,SM64.PRX}
```

Audio is generated through the Media Engine with `libme-core`; no external sound PRX is needed next to the EBOOT.

## 7. For developers

### Profiling with gprof

1. Build with profiling: `make TARGET_PSP=1 PROFILE_PSP=1` (add `pbp` for an EBOOT).
2. Run it on the PSP or emulator. `gmon.out` is written when the game exits normally.
3. Copy `gmon.out` back and analyse it: `gprof build/us_psp/sm64.us gmon.out > profile_report.txt`

Profiling adds overhead. With it enabled, the PBP uses the ELF directly instead of a PRX.

### Other targets (unchanged from upstream, not maintained in this fork)

The upstream project can also build native **Linux** and **Windows (MSYS2)** executables and N64 ROMs.
See [sm64-port/sm64-port](https://github.com/sm64-port/sm64-port) and [n64decomp/sm64](https://github.com/n64decomp/sm64) for those instructions.

### Project structure

```
sm64
├── actors: object behaviors, geo layout, and display lists
├── asm: handwritten assembly code, rom header
├── assets: animation and demo data
├── bin: C files for ordering display lists and textures
├── build: output directory
├── data: behavior scripts, misc. data
├── enhancements: example source modifications
├── include: header files
├── levels: level scripts, geo layout, and display lists
├── lib: SDK library code
├── psp: PSP icon, background and sound for the EBOOT, PSP-specific textures
├── rsp: audio and Fast3D RSP assembly code
├── sound: sequences, sound samples, and sound banks
├── src: C source code for game
│   ├── audio: audio code
│   ├── buffers: stacks, heaps, and task buffers
│   ├── engine: script processing engines and utils
│   ├── game: behaviors and rest of game source (psp_options.c = the Options menu)
│   ├── goddard: Mario intro screen
│   ├── menu: title screen and file, act, and debug level selection menus
│   └── pc: port code, audio and video renderer (PSP: gfx_psp.c, audio_psp.c, psp_me.c)
├── text: dialog, level names, act names
├── textures: skybox and generic texture data
└── tools: build tools
```
